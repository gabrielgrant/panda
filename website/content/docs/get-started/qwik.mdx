Learn how to set up Panda CSS in a Qwik 2 project (`@qwik.dev/core`) using the `@pandacss/vite` plugin.

Prefer PostCSS? Run `panda init --postcss` instead of the plugin step below and follow
[Using PostCSS](/docs/get-started/postcss). Everything else on this page stays the same.

### Add the Vite plugin

Add `pandacss()` to your Vite plugins. It generates the `styled-system` folder, injects the CSS, and keeps both up
to date on save. No separate watcher needed.

```ts {2,8} filename="vite.config.ts"
import { defineConfig } from 'vite'
import pandacss from '@pandacss/vite'
import { qwikVite } from '@qwik.dev/core/optimizer'
import { qwikRouter } from '@qwik.dev/router/vite'
import tsconfigPaths from 'vite-tsconfig-paths'

export default defineConfig({
  plugins: [pandacss(), qwikRouter(), qwikVite(), tsconfigPaths()]
})
```

### Update package.json scripts

Open your `package.json` file and update the `scripts` section as follows:

```diff {3} filename="package.json"
{
  "scripts": {
+    "prepare": "panda codegen",
    "dev": "vite --mode ssr",
    "build": "qwik build",
    "preview": "qwik build preview && vite preview --open"
  }
}
```

The plugin only runs with Vite. The `"prepare"` script covers type checking and your editor, which read
`styled-system` before Vite starts, and lets the folder stay gitignored.

### Configure the content

Set `jsxFramework: 'qwik'` and make sure your component paths are in `include`:

```js {6,7} filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  presets: ['@pandacss/preset-base', '@pandacss/preset-panda'],
  preflight: true,
  include: ['./src/**/*.{js,jsx,ts,tsx}'],
  jsxFramework: 'qwik',
  outdir: 'styled-system'
})
```

`jsxFramework: 'qwik'` generates `styled`, the pattern components, `createRecipeContext`, and
`createSlotRecipeContext` in `styled-system/jsx`. They target Qwik 2 and render with `class`.

### Configure CSS layers

Declare the layer order at the top of `src/global.css`, which Qwik already imports in `src/root.tsx`:

```css filename="src/global.css"
@layer reset, base, tokens, recipes, utilities;
```

This file only sets the layer order. The plugin injects the generated CSS for you.

### Start using Panda

Now you can start using Panda CSS in your project.

```tsx filename="src/routes/layout.tsx"
import { component$, Slot } from '@qwik.dev/core'
import { routeLoader$ } from '@qwik.dev/router'
import { css } from 'styled-system/css'

export const useServerTimeLoader = routeLoader$(() => {
  return {
    date: new Date().toISOString()
  }
})

export default component$(() => {
  return (
    <div class={css({ p: '10', bg: 'gray.900', h: 'dvh' })}>
      <Slot />
    </div>
  )
})
```

### Use the JSX helpers

Style props, recipes, and Qwik props such as `onClick$` all go through `styled`:

```tsx filename="src/routes/index.tsx"
import { component$, useSignal } from '@qwik.dev/core'
import { createSlotRecipeContext, styled } from 'styled-system/jsx'
import { card } from 'styled-system/recipes'

const { withProvider, withContext } = createSlotRecipeContext(card)
const Card = withProvider('article', 'root')
const CardTitle = withContext('h2', 'title')

export default component$(() => {
  const count = useSignal(0)
  return (
    <Card size={count.value % 2 ? 'lg' : 'md'}>
      <CardTitle>Clicked {count.value} times</CardTitle>
      <styled.button px="4" bg="blue.500" onClick$={() => count.value++}>
        Click
      </styled.button>
    </Card>
  )
})
```

Create recipe contexts and their parts at module scope, since a `component$` can only use bindings from there. Parts
can wrap tags, `component$` components, or plain function components, and their options don't need to be
serializable.

A context's id comes from its recipe, so the server and the resumed client agree on it. When one recipe backs two
contexts, give each its own `id` (in development, Panda warns when you don't):

```tsx
const menu = createSlotRecipeContext(listbox, { id: 'menu' })
const select = createSlotRecipeContext(listbox, { id: 'select' })
```

### Optional: drop the styling runtime

By default `css()` resolves class strings in the browser with a small runtime. Turn on source transforms and the
plugin rewrites static calls to plain class strings at build time, so the runtime never ships:

```ts filename="vite.config.ts"
plugins: [pandacss({ transform: true }), qwikRouter(), qwikVite(), tsconfigPaths()]
```

Dynamic values keep their runtime form. See [Source transforms](/docs/styling/source-transforms).

## Troubleshooting

If you're not getting import autocomplete in your IDE, you may need to include the `styled-system` directory in your
`tsconfig.json` file:

```json filename="tsconfig.json"
{
  // ...
  "include": ["src", "styled-system"]
}
```
